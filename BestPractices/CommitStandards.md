# Commit Message Standards

We aim for clear and meaningful commit messages that help us understand the changes made to the project. Following these guidelines will make it easier to navigate and track progress.

### General Guidelines:

1. **Atomic Commits** – Each commit should represent a single logical change or unit of work. Avoid mixing unrelated changes in the same commit to ensure that each change is easy to understand, test, and revert if necessary.
2. **Keep it concise and clear** – Commit messages should briefly describe the "what" and the "why" of the changes.
3. **Use imperative mood** – Start commit messages with a verb, e.g., "Fix", "Add", "Refactor", etc.
4. **Capitalize the message** – Always start the commit message with a capital letter.
5. **GitHub Issue Reference** – If the commit relates to a GitHub issue, include the issue number at the **beginning** of the commit message. This helps link the work to the relevant discussion.

   Example:

   ```
   #123 Fix login bug on the user dashboard
   ```

By following these simple standards, we can maintain clarity and traceability in our commit history.
